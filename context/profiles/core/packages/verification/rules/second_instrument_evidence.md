# Second-Instrument Evidence

Output used as verification evidence is re-derived through a second pinned instrument — HEAD blobs via `git show` plus a pinned `diff`, raw output by bypassing the wrapper, cleanup that bypasses interactive aliases, unpiped exit codes — never through a `PATH` wrapper alone.

Any output that decides an action or lands in evidence is re-derived through a second instrument that bypasses the `PATH` wrapper that produced it — this is a documented recipe, applied without re-derivation per incident. The four canonical forms: (1) committed-file comparisons extract HEAD blobs (`git show HEAD:<path> > /tmp/<base>`, then `/usr/bin/diff /tmp/<base> <worktree-file>`), never a wrapped `diff`, which can synthesize "identical" for filtered-away changes; (2) wrapper-mangled output is re-run raw, through the wrapper's own pass-through mode or by invoking the real binary by absolute path — a wrapper mislabeled Biome output as ESLint and a pipe made the exit code meaningless; (3) scratch cleanup bypasses shell aliases (`command rm`), because an interactive `rm -i` alias silently declines deletes and left mutation labs persisted after "cleanup"; (4) gates and state-changing commands run unpiped so `$?` is theirs — "INSTALL_EXIT=0 is a lie: I piped through tail, so $? was tail's" — and the literal exit code is recorded. During a live security review a git shim dropped three real files from a status listing and swallowed diff hunks; every validator that day independently re-derived this recipe, which is exactly the cost the recipe exists to remove.

The host-specific forms of these instruments (which wrappers and shims a given machine installs, and their raw-invocation spellings) belong in that host's private context.
