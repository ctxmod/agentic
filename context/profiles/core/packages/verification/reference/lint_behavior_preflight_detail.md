# Lint-vs-Behavior Pre-Flight — Detail

The full lint-vs-behavior pre-flight rule with its worked incident, for the [lint_behavior_preflight](../rules/lint_behavior_preflight.md) rule.

Before committing to a UI pattern that a linter rule may flag, probe whether the rule is configurable (its options schema, at the pinned version) and whether an honest-semantics variant passes — choosing the pattern first is how a full accessibility rework got inserted between a failed release and its retry (the linter's keyboard-target rule had `additionalProperties: false`, zero configurable exceptions, so every honest labelled focusable scroll region failed it, and the 2026-10-06 ruling rebuilt the region as an ARIA feed with roving tabindex rather than suppress). When a lint finding meets a behavior, the fix may restructure but may never remove the behavior: accessibility targets and error states are not lint findings, and a coordinator rejected exactly that shortcut during the same incident ("Removing focusable scroll target is not acceptable"). The only sanctioned escape when rule and honest behavior are irreconcilable is an explicit, authorized, scoped override carrying a naming comment that says what is overridden and why — never a fake interactive role, a tabIndex workaround, or a silent suppression.
